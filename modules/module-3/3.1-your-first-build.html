Base44 Walkthrough: Your First Build

Blank screen to a real, working app. By the end of this lesson you'll have published something live in Base44 — not a demo, an actual URL you can send someone.

Before you start this lesson
  • A free Base44 account, created through the course signup link (this is what makes the course free — see Module 1.1 if you skipped it)
  • 15–20 minutes uninterrupted — this is a build-along, not a watch-later video
  • Nothing else. No code editor, no hosting account, no credit card.

This is the most important lesson in the course to actually do, not just watch. Everything downstream — the scraper in 2.2, your business backend in 3.3, the client deliverable in Module 6 — is the same underlying skill repeated. Get comfortable with it once here, with nothing on the line, and it stops being a bottleneck later.

What you'll build

A simple internal tracker: a list of contacts (name, business, status, notes) with the ability to add, edit, and mark a status. It's intentionally small. The goal isn't the app — it's the muscle memory of going from a plain-English description to a published, working product inside Base44.

Base44 step Open Base44, start a new project, and paste the prompt below exactly as written. Don't summarize it in your own words yet — the specificity in the prompt is doing real work.

The prompt

Copy this in full. This is the literal text to paste into Base44's build prompt, not a paraphrase of what to type.

Base44 build prompt select all, copy, paste into Base44 
Build me a simple contact tracker app called "Client Pipeline."

It should have:
- A table of contacts with these fields: Business Name, Contact Name, Phone, Email, Status, Notes
- Status should be a dropdown with these options: New Lead, Contacted, Demo Booked, Proposal Sent, Won, Lost
- A button to add a new contact via a simple form
- The ability to click a row and edit any field, including changing the Status
- The main view should be sortable by Status, and show the most recently updated contacts first
- Keep the design clean and minimal — no unnecessary graphics or filler content

This is an internal tool I'll use daily, so prioritize speed of data entry over visual polish.

Steps

  1. Paste the prompt above into a new Base44 project and let it generate the first version.
  2. Open the generated app and add three test contacts by hand — this is the fastest way to catch anything that feels off before you rely on it.
  3. If a field or behavior isn't right, describe the fix in plain English back to Base44 rather than trying to hand-edit anything. Treat the prompt box as the primary way you work, even for small corrections.
  4. Once it's usable, publish it. Base44 gives you a live URL — open it in a new tab to confirm it actually works outside the editor.
What you should have when this lesson is done A published, working Client Pipeline app with a live URL, and three real (or test) contacts in it. If you don't have a URL you can open in a fresh tab, this lesson isn't finished yet — go back and publish before moving on.

Why this specific exercise

This tracker isn't throwaway — you'll actually use it in Module 4 to track outreach once you start contacting real businesses. Module 3.3 builds this out further into a full business backend. Nothing you build in this course is a disposable practice exercise; everything either becomes a tool you keep using or a pattern you repeat for a client.
